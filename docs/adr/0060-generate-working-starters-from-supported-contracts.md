# ADR-0060: Generate working starters from supported contracts

**Status:** accepted

## Context

The starter pack must execute through the supported compiler and runtime, preserve verification,
and work without accounts. Copying proposal examples or shipping placeholder pins would leave
developers with definitions that look plausible but cannot be admitted. A bounded command Worker
also needs to declare which natural-language goal and claim types it can actually assess.

Embedding the originating goal into shared command code prevents safe export. Public specification
contracts must describe reusable behavior without acquiring a Task's private prose.

## Decision

Extend the absent-destination starter factory with `software`, `planning` and `all` profiles.
Construct definitions using the supported typed Pipeline and Worker models, validate them, and
derive package pins and verifier-policy IDs from the actual emitted bytes. Emit exact contract
fixtures. The `all` profile combines software and document definitions under one captured catalog.
Review and commit the generated authority before execution.

Provide small and heavy implementation, light and heavy Review, independent verification,
reviewed implementation, targeted and heavy repair, and document Pipelines. Each has explicit
public contracts and resource bounds. Share Worker packages across those definitions. Heavy
implementation permits a bounded author retry; heavy Review declares two discovery calls.
Targeted and complete repaired-Review acceptance retain distinct contracts. Required reviewers
are never dropped to make a strategy cheaper.

Ship a reusable Planner Worker for the installed fixed preparation Pipeline. Its proposal fixture
is emitted from a supported typed reviewed-implementation definition. A no-fit tutorial changes
the applicability fact and invokes the same bounded Planner/approval path as model planning.
Enabling it requires a supplied developer public key; Afactory never creates or imports a private
signing key. Existing fits still spend no Planner Attempts.

Command substitutes perform actual pagination, invalid-bound, input-preservation, source and
document checks. They support explicit tutorial requirements. The independent fix verifier returns
inconclusive for unknown claim types. The shipped author implements its whole supported goal;
tests inject an explicitly faulty Worker to exercise repair. No default Worker is deliberately
broken, and a fixture result is not a model performance claim.

Keep ADR-0057's export guard unchanged, including originating Task text in shared Worker files.
Task files may supply a bounded nonempty `requirements` object, captured as `specification` beside
the descriptive goal in the Requirements input. This object is business data and grants no
execution authority. The software command substitutes accept only the published structured
pagination specification; they do not interpret arbitrary prose. A capability fact lets the bounded
Planner select its tutorial proposal, but only execution and independent verification establish
acceptance. Exported Workers check the public specification and never embed the originating goal.

## Consequences

The CLI fixtures compile and run the emitted software and document catalog without paid inference,
exercise both repair guarantees, preserve incomplete review, and replay finished Tasks exactly.
The planning fixture pauses before generated execution, exports without approving, verifies
unchanged shared Worker bytes, records a detached developer signature, executes and imports the
bundle into a second checkout with zero Planner calls. The existing generated-private-text refusal
fixture remains required. Broader model tuning and live performance remain P14 evidence.
