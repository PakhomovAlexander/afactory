# Performance evidence archive: collector runbook

The continuous performance laboratory keeps run evidence in CI artifacts only as transport: pull
request evidence for 14 days and main, nightly and release evidence for 90
([design §11](design/continuous-performance.md#durable-archive)). A trusted collector copies it
into a content-addressed filesystem archive that outlives that expiry
([ADR-0172](adr/0172-admit-candidate-files-through-bounded-descriptors-and-report-archive-and-trend-runs-offline.md)).
This runbook says how to provision and operate that collector, and what has and has not been
demonstrated.

## What is provisioned

- **A persistent filesystem** on a host the operator trusts. It is not a benchmark host and
  runs no candidate code. The archive root must be a real directory, not a symlink.
- **Capacity.** The default is 100 GiB. Choose another at creation with `--capacity-bytes`, at
  most 1 TiB without a reviewed policy change. The filesystem also needs free space beyond each
  import plus a 64 MiB margin.
- **One credential.** A fine-grained token restricted to the one configured repository, with
  read access to its contents and Actions. It is held in the collector's environment only. No
  benchmark, build or shard ever receives it: their environments are built from allowlists.
- **No workflow change is made by the collector.** It posts no comment, writes no ref and
  changes no ruleset.

## Commands

Create the archive once:

```sh
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive --init
```

Import a run directory verified locally, for example one assembled by `cli.py aggregate`:

```sh
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive --import RUN_DIR
```

Collect one Actions run's transport artifacts:

```sh
export AF_PERF_ARCHIVE_TOKEN=...   # read-only, this repository only
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive \
  --fetch ACTIONS_RUN_ID --repository OWNER/NAME
```

One Actions run of the continuous workflow can hold several laboratory runs, each in its own
`af-perf-<run>-run` and `af-perf-<run>-shard-<i>` artifacts. The collector refuses to mix them:
add `--lab-run RUN_ID` to collect one, once per laboratory run
([ADR-0177](adr/0177-schedule-continuous-runs-from-trusted-control-and-move-builds-once-to-bounded-shards.md)).

`--api-url` names another API origin, such as GitHub Enterprise Server's
`https://HOST/api/v3`; the token is sent only there. `--token-env` names another variable.
Each request, its connection, TLS, headers and body included, ends by one absolute deadline:
the earlier of 60 s and what is left of the collection's 30 minutes. A server that sends slowly
is refused at that deadline, and redirect hops share the collection's
([ADR-0173](adr/0173-own-the-supervisor-a-test-runs-and-bound-admission-collection-scratch-and-cancellation-by-absolute-deadlines.md)).

Apply retention, then report health:

```sh
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive --retain
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive --status
```

Pin a run that is an active calibration cohort member or a release-budget demonstration, and
supersede it when a later run replaces it:

```sh
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive \
  --pin RUN_ID --reason active_cohort --note "cohort c1"
python3 scripts/performance/cli.py archive --root /srv/af-perf-archive \
  --supersede RUN_ID --superseded-by NEW_RUN_ID
```

Browse what was archived, with each run's report regenerated by the trusted renderer:

```sh
python3 scripts/performance/cli.py history --inputs /srv/af-perf-archive --output DIR
```

Every command takes the archive's lock; a second concurrent command refuses.

## Scheduling

Run the bounded collector hourly, well inside the shortest transport retention (14 days).
It discovers completed runs, imports each laboratory run, pins calibration evidence, applies
retention and renders history. A cron entry or a systemd timer on the collector host is enough:

```cron
15 * * * * cd /srv/af && timeout 35m python3 -I scripts/performance/collect.py --root /srv/af-perf-archive --history /srv/af-perf-history --repository OWNER/NAME
```

The token is supplied through `AF_PERF_ARCHIVE_TOKEN`, or use `--gh-auth` for an existing
authenticated GitHub CLI on the archive host. See [SDLC integration](performance-sdlc.md) for
deployment, catch-up bounds and the distinction between archive health and a qualified check.

## What health means

`--status` exits 4 and lists problems when:

- **`capacity_exhausted`**: the last import needed more than the capacity or the filesystem's
  free space. Nothing was imported and the source evidence was untouched. Raise the capacity
  within 1 TiB or add space, then fetch again before the transport expires.
- **`capacity_low`**: less than a tenth of the capacity remains.
- **`collection_failed`**: the last collection refused a transport or a run, and its detail says
  why. A refused artifact is never retried silently.
- **`transport_expiring`** or **`transport_expired`**: an artifact a collection listed was not
  archived and expires within 7 days, or already has. An expired artifact leaves its run's
  retained evidence incomplete, and its verdict says so.
- **`no_collection`**: nothing was ever collected.

It also reports the last successful collection and the collection lag, from a run's evidence
ending to its archiving.

## Retention

Numeric samples, plans, build manifests, verdicts and summaries are kept at least 365 days from
admission. Logs, transported views, profiles and their symbols are kept 90 days. A pinned run is
kept whole until it is superseded and then 365 days more.

Expiry writes an explicit retention entry with the run's original manifest and what remains.
Garbage collection removes only objects no remaining member of any run references, so a shared
object stays while any run needs it. Space is never a reason to remove anything. A run whose
logs or symbols expired is shown from its archived summary, and nothing claims that it can still
be reproduced in full.

## What is demonstrated, and what is not

The package's tests and the local demonstration recorded with ADR-0172 cover:

- a real local archive: import, idempotent re-import, retention, pins, garbage collection,
  capacity exhaustion and status;
- the collector against a fake transport, with the token confined to the API origin and no
  signed location recorded.

They do not demonstrate:

- an authenticated collection from GitHub;
- the performance workflows that upload `af.perf-transport/1` artifacts (package p6a);
- unattended scheduled collection;
- collection before transport expiry on a real schedule;
- archive capacity under real load.

Continuous history must not be claimed until an operator has provisioned this collector, observed
it collect real runs before their transport expired, and kept its status healthy.
