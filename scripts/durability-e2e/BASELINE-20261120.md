# Native AF durability baseline · 20 November 2026

The manual suite ran against AF 0.15.1, binary SHA-256 `bd79ea23b6a1ddc82be0def4c6f118cbdd2e4bc3a53b8da84c785eabc229a283`. The three broker cases used the same Git workload and separate engine and Checks VMs. The control host relayed the receipt, and the verifier compared the independent Checks ledger with the saved AF Task and Scenario history.

| Broker case | Outcome | Seconds from receipt delivery | Verdict |
| --- | --- | ---: | --- |
| Clean control | Original Scenario succeeded | 0.653 | Pass |
| Green check after scheduler death | Original Scenario succeeded | 0.141 | Pass |
| Red check after scheduler death | Original Scenario failed and its Checks step remained running | 0.136 | Invariant failure |

Each case created one check and recorded zero repeated steps and zero real provider tokens. The timings exclude broker and relay latency and describe single observations. See the [normalized comparison records](baselines/2026-11-20/). These records summarize the observed runs. The original deployment's job logs, private ledgers and raw operational evidence were retained outside Git.

Separate one-VM trials exercised additional fault boundaries:

| Case | Observed native result |
| --- | --- |
| CI or network interruption | A lost create reply and HTTP 503 left a durable reconciliation wait. The restarted scheduler found the original check and Task. A green receipt for a different candidate was ignored until the matching receipt arrived. |
| Expired GitHub fixture credential | Witnessed HTTP 401 and rotated the fixture credential. A normal restart reconciled the original check and completed the same Scenario. |
| Required gate and repair | A real local check rejected candidate A. One separately captured repair produced candidate B, which passed a new check and independent evaluation. Both outcomes remained inspectable. |
| Task budget and malformed usage | A provider fixture reported 4,097 tokens against a 4,096-token reservation. The Task stopped with no additional author call. A funded control finished. After a lost charge reply the reservation remained exposed. With a malformed usage field AF charged the full reserve without marking the amount unknown. |
| Hostile provider output | The captured evaluator requirement held. Malformed output stopped after one bounded re-ask, and the terminal step invariant failed. |
| Full journal volume | A real SQLite write hit ENOSPC. After space returned and the scheduler restarted normally, the original Scenario finished. |
| Full artifact volume | A real CAS temporary write hit ENOSPC. All 164 existing objects survived with unchanged Task history, and the original Scenario remained failed after space returned. |
| Writer loss | AF replaced the writer after its production lease expired, advanced the writer epoch, retained an abandoned Attempt with unknown usage, and verified the same Task. Time from kill to terminal evidence was 61.281 s. |
| Child cancellation | A persisted process-scoped cancel stopped the child, then scheduler replay redispatched that child. The durable child cancellation contract failed. |
| Ant pause and slot reuse | A busy occurrence skipped admission, the original Run settled, and the next eligible occurrence admitted a distinct Task. A separate pause persisted across restart and blocked new admission until explicit re-enable. |

The native adapter reports cross-VM Task replacement and stale completion delivery as `unsupported`. The broker profile separates the Checks dependency from the engine and exercises recovery from scheduler process death. A future Worker placement adapter can run the independent-Worker profile with the same case contract.

## Refactor targets

1. Settle each active step and its intent when recording a terminal Scenario outcome.
2. Preserve a typed, recoverable publication intent when infrastructure prevents an artifact write.
3. Record child cancellation as an orchestration decision that the parent observes on replay.
4. Keep confirmed usage, reserved exposure and unknown settlement distinct in durable accounting.
